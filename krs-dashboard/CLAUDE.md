# Контекст для Claude Code — дашборд KRS/Кайрос

Веб-дашборд продаж ООО «Кайрос» (HeadRock/KRONbuild/ENKI). HTML + Python-скрипт.

## Архитектура
- Данные и вёрстка РАЗДЕЛЕНЫ. Дашборд читает объект `window.KRS_DATA` внутри HTML.
- `build_data.py` парсит 3 Excel из `data/`, генерит KRS_DATA, вставляет в
  `KRS_template.html` → пишет `KRS_real_data.html`.
- Правки ЦИФР/ЛОГИКИ → в `build_data.py`. Правки ВИДА → в `KRS_template.html`.
  НЕ редактировать данные прямо в KRS_real_data.html — перезапишутся.
- В KRS_DATA есть `tx` (транзакции с датами до SKU) — на них работает фильтр периода
  на клиенте (JS-функция `clientByPeriod`) и на Обзоре (`recompute`).

## Как устроены Excel (нетривиально — не переизобретать)
- Продажи по бизнес-регионам: 3 блока. Блок1 менеджеры→клиенты (свод, Итого сходится
  до рубля). Блок2 регионы→клиент→ЗАКАЗ→РЕАЛИЗАЦИЯ→товар (outline-уровни). Товары берём
  ТОЛЬКО как листья поддерева клиента (иначе двойной счёт). Дата берётся со строки ЗАКАЗА.
  «Заказы в работе» = сумма заказа минус сумма его Реализаций. Возвраты — суммы со знаком −.
- Прайс: лист HeadRock (артикул col B), лист KRONbuild (артикул col A, бренд ENKI по
  заголовку секции). Даёт бренд/категорию/цену.
- ABC-отчёт: остатки склада «Лакония ОПТ» (col 173–179: в наличии/отгружается/резерв/
  доступно/поступит/всего). ABC там по 32 клиентам — НЕ основа; ABC считаем сами из транзакций.

## Ограничение
Товар↔прайс по названию ~63%. Артикул в выгрузке продаж → 100%. Fuzzy-матч не тащить
(путает размеры Р40↔Р150).

## Частые задачи
- Обновить данные: свежий Excel в data/ → `python build_data.py`.
- Распространить фильтр периода на др. вкладки: по образцу `clientByPeriod`/`recompute`.
- Новый бренд/филиал/план: расширить build_data.py (там где сейчас null).
- Правка вида блока: KRS_template.html, затем пересобрать скриптом.
