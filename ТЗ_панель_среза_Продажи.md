# ТЗ: панель среза на вкладке «Продажи → Результаты продаж»

Статус: реализовано в прототипе `Kairos_dashboard_proto.html` (источник вёрстки — `Kairos_proto_template.html`, данные подставляет `rebuild.py`). Документ описывает текущее поведение и критерии приёмки; пункты в разделе 9 — открытые вопросы.

## 1. Цель

Дать одну связную картину «как мы продаём в выбранном срезе»: сколько и чего продаём, где представлены, где нет, кто покупает, что покупают, как это соотносится с планом и со всей компанией. Срез задаётся общими фильтрами и кликом по карте. Экран показывают на планёрках, поэтому цифры крупные, выводы читаются без раскрытия.

## 2. Логика среза

- Срез = пересечение общих фильтров: период, филиал, регион, город, бренд, менеджер, клиент, категория, товар. Клик по региону на карте (или в списке) добавляет/снимает регион в фильтре.
- Без выбранных фильтров срез = вся компания. Панель показывается всегда.
- Все блоки страницы считаются по одному и тому же срезу и одному периоду. Сравнение — с тем же периодом прошлого года (АППГ).
- Заголовок панели: «Срез: <уровень>» (вся компания / филиал / регион / город / менеджер / клиент) и строка выбранных фильтров. Кнопка «Сбросить» видна, только если что-то выбрано.
- Канал «Сети» не привязан к городам: блоки по городам заменяются пометкой «федеральный канал».

## 3. Порядок блоков на странице (сверху вниз)

1. Фильтры и метки выбранного.
2. Верхняя полоса: продажи, выполнение плана, клиенты, заказы, средний чек, штуки, SKU (с Δ к АППГ).
3. Динамика: продажи по месяцам (факт/план) и по брендам.
4. Блок «Регионы и покрытие»: карта.
5. Панель среза (разделы 4–6).
6. Разбивка продаж (таблица с переключателем разреза).

## 4. Панель среза: состав и поведение

### 4.1 Тёмный герой «Покрытие городов» (слева)
- Главная цифра: доля крупных городов справочника, в которых есть продажи в срезе = города с продажами / все города территорий среза.
- Подпись «продаём в N из M крупных городов» и вердикт словами: ≥60% «уверенное покрытие», 30–59% «есть куда расти», <30% «слабое покрытие».
- Четыре показателя: доля среза в продажах компании; число компаний с Δ к АППГ; доля A-позиций компании, которые берёт срез (N из M); число городов, просевших к АППГ.
- Кнопка «ABC-анализ среза ›» ведёт на вкладку «Ассортимент и ABC» с тем же срезом.

### 4.2 «Где продаём» (справа)
- Список городов с продажами по убыванию, столбец-«таблетка» и сумма; максимальный город выделен красным, остальные графитовые. Прокрутка внутри блока.
- «Не продаём»: счётчик и серые чипы городов без продаж (до 30, далее «+ ещё N»).
- «Просели»: города, где продажи ниже АППГ более чем на 20%; чипы с процентом падения (до 12), красным выделен только процент.

### 4.3 Покрытие по брендам (тёмная карточка)
KRONbuild, ENKI, HeadRock: фирменная плашка, продажи, доля бренда, число городов и компаний с продажами бренда. При фильтре по одному бренду показывается только он.

### 4.4 ABC среза
Для классов A/B/C: доля позиций компании этого класса, которые берёт срез (шкала), «N из M позиций», число компаний класса и их доля выручки. Под блоком — список A-позиций, которые срез не берёт (до 4). Классы позиций — эталон по всей компании.

### 4.5 Категории и топ-10 товаров
Полукруг категорий (доли выручки среза) и 10 товаров с наибольшими продажами среза. Блок использует существующую разметку вкладки.

### 4.6 Компании
- «Компании среза»: топ-10 по выручке в срезе: название, ABC-класс внутри среза (по накопленной выручке 80/95%), сумма, Δ к АППГ («новая» — если не покупала в АППГ). Счётчик «новых». Клик — карточка компании.
- «Потеряли компаний»: покупали в АППГ, в периоде покупок нет; счётчик, сумма прошлого периода, топ-10 по прошлым продажам.

### 4.7 Ведущий менеджер
Строка внизу: менеджер с наибольшими продажами в срезе.

## 5. План

- План задан по каналам «ОПТ Москва», «ОПТ Владивосток», «Сети» и группам брендов «KRONbuild+ENKI», «HeadRock» по месяцам (`План_25_26.xlsx`).
- План среза = сумма по выбранным филиалам × брендам за месяцы периода до последнего месяца с данными. Выполнение = факт среза / план YTD среза. Показывается в верхней полосе и на графике динамики.
- План не показывается (прочерк и пояснение), если выбран регион, город, менеджер, клиент, категория или товар, либо один из брендов KRONbuild/ENKI без второго (план задан на них вместе).
- Контроль: для среза «вся компания» план YTD совпадает с вкладкой «Обзор».

## 6. Визуальные требования

Опираться на вкладку «Обзор» и `Дизайн/РЕФЕРЕНСЫ.docx`, брендбук «Кайрос 2026» (по `PRODUCT.md`).
- Графит `#2A2A2A`, белый, тёплый серый `#CAC4B8`/`#EEEBE4`; красный `#C7001F` — только внимание и негатив; жёлтый `#FDCF08` — поддержка и главная кнопка.
- Шрифты: Unbounded — заголовки и крупные цифры; Montserrat — текст. Подписи капсом с маркером «•».
- Тёмные карточки с красно-жёлтым свечением для главного вывода (как в «Обзоре»), белые карточки с радиусом 20–22 px, градиентные полосы «жёлтый → красный», подъём карточки при наведении.
- Разные формы данных: столбцы, полосы, полукруг, таблица. Без случайных цветных заливок: зелёный/красный только как статус.
- Адаптив: на ширине до 1000 px блоки в одну колонку.

## 8. Критерии приёмки

1. Без фильтров панель показывает всю компанию; план YTD равен значению в «Обзоре».
2. Выбор региона кликом по карте, из фильтра и из списка даёт одинаковый срез; все блоки обновляются синхронно.
3. Для среза «Сети» нет городских блоков и нет ошибок в консоли.
4. Для среза «Москва» план показывается, для «Москва + Южный ФО» — нет, с понятным пояснением.
5. Сумма «Где продаём» не превышает продажи среза; города из «Не продаём» не имеют продаж в срезе.
6. Клик по компании открывает её карточку; кнопка ABC открывает вкладку «Ассортимент и ABC» с тем же срезом.
7. Файл открывается двойным кликом офлайн; нет ошибок JS на сценариях: вся компания, филиал, регион, бренд, «Сети».

## 9. Открытые вопросы и ограничения

- «Москва» и ряд городов попадают в «Не продаём», хотя продажи есть: они учтены по региону, а не по городу. Нужно решение по привязке.
- Порог «просели» (−20%) и «крупные города» (справочник) — настраиваемые параметры; значения нужно подтвердить.
- ABC компаний считается внутри среза; нужен ли рейтинг относительно всей компании.
- План по региону/менеджеру отсутствует в источнике; нужен ли план с этим уровнем детализации.
- Категории в референсе (лента-«воронка») пока не реализованы, оставлен полукруг.
- Нет данных по себестоимости, марже и скидкам.
