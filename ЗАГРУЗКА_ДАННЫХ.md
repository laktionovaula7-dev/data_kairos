# Обновление данных прямо в дашборде

Кнопка **«Данные на дд.мм.гггг · обновить»** справа в верхней панели открывает окно загрузки.

## Что загружать (три выгрузки из 1С, формат .xlsx, без правок)
| Файл | Обязателен | Что даёт |
|---|---|---|
| Продажи по бизнес регионам (период с 01.01.2024 по сегодня; подразделения Москва / HeadRock МСК / Владивосток / HeadRock Владивосток / СЕТИ; бренды ENKI, KRONbuild, HeadRock) | да | все продажи, клиенты, регионы/города, ABC, менеджеры, «Обзор» |
| Остатки и доступность по сериям (все склады) | нет | остатки и оборачиваемость; если не загружать — остаются прежние |
| Товары на складах с окончанием срока годности | нет | сроки годности; если не загружать — остаются прежние |

Файлы можно перетащить в окно все сразу — тип определяется по названию файла («продаж», «остатк», «годност/срок»).

## Что происходит
1. Дашборд читает Excel прямо в браузере (интернет не нужен, файлы никуда не отправляются). Продажи ≈ 5–40 секунд.
2. Показывает сводку: «данные на …», нетто продаж было → стало, число клиентов, отбор в файле, предупреждения
   (файл старее текущих данных, в закрытых месяцах цифры изменились, новый период короче прежнего, новые клиенты без CRM).
3. По кнопке **«Применить»** данные сохраняются в браузере (IndexedDB) и дашборд перезагружается уже на новых данных.

## Что остаётся «зашитым» в файл при сборке
Прайс (бренд/категория по артикулу), план 25/26, карточки CRM и ИНН, справочник городов, карта, население.
Они обновляются запуском `python rebuild.py` (как раньше). Загруженные в браузере данные берут эти справочники из самого файла.

## Передать данные коллеге
Окно загрузки → **«Сохранить текущие данные в файл»** (получится `kairos_data_ДАТА.kairos`) → коллега открывает у себя
**«Открыть файл данных»**. Загрузка в браузере действует только в том браузере, где её сделали.
**«Вернуть данные из файла»** удаляет загруженное и показывает данные, зашитые при сборке.
Если зашитые данные новее загруженных (после свежей сборки `rebuild.py`), дашборд сам покажет зашитые.

## Как устроено и как проверить
* `kairos_ingest.js` — чтение xlsx (zip + потоковый разбор листа) и расчёт модели; это порт `parse_sales` / `build_krs` из `rebuild.py`.
* `kairos_ingest_ui.js` — окно, хранение в браузере, запуск приложения.
* Обе части встраиваются в итоговый HTML при сборке (`selfcontain.py`).
* **Любое изменение расчётов в `rebuild.py` нужно повторить в `kairos_ingest.js`.** Проверка совпадения:
  `python rebuild.py && node check_ingest_parity.cjs` — сравнивает браузерный пересчёт с моделью Python по всем разделам.
